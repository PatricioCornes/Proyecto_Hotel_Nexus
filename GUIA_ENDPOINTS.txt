GUIA RAPIDA DE ENLACES, PUERTOS Y CUERPOS JSON
PROYECTO HOTEL NEXUS

Esta guia esta pensada para ejecutar peticiones desde Postman, Insomnia o
Swagger. Reemplazar {id}, {codigo} y los datos de ejemplo por valores que
existan en la base de datos.


1. INFRAESTRUCTURA

Eureka:
http://localhost:8761

RabbitMQ AMQP:
localhost:5672

RabbitMQ Management:
http://localhost:15672
Usuario por defecto: guest
Clave por defecto: guest

MySQL / Laragon:
localhost:3306
Usuario por defecto: root
Clave por defecto: vacia

IMPORTANTE:
No ejecutar al mismo tiempo MySQL de Laragon y el contenedor nexus-mysql si
ambos intentan ocupar el puerto 3306.

3. REGLA GENERAL PARA EL CRUD

Listar:
GET http://localhost:{puerto}/{recurso}
Sin cuerpo JSON.

Buscar por id:
GET http://localhost:{puerto}/{recurso}/{id}
Sin cuerpo JSON.

Agregar:
POST http://localhost:{puerto}/{recurso}
Header: Content-Type: application/json
Usar el cuerpo indicado para el microservicio.

Modificar:
PUT http://localhost:{puerto}/{recurso}/{id}
Header: Content-Type: application/json
Usar el mismo formato completo utilizado para agregar.

Eliminar:
DELETE http://localhost:{puerto}/{recurso}/{id}
Sin cuerpo JSON.


4. STAFF - EMPLEADOS

Listar: GET http://localhost:8080/empleados
Buscar: GET http://localhost:8080/empleados/{id}
Agregar: POST http://localhost:8080/empleados
Modificar: PUT http://localhost:8080/empleados/{id}
Eliminar: DELETE http://localhost:8080/empleados/{id}

{
  "run": "12.345.678-5",
  "nombre": "Camila",
  "apellido": "Soto",
  "fechaNacimiento": "1995-04-10",
  "correo": "camila.soto@hotel.cl",
  "telefono": "+56912345678",
  "turno": "MANANA",
  "cargo": "LIMPIEZA"
}

Asignar empleado disponible por cargo:
POST http://localhost:8080/empleados/interno/asignar/LIMPIEZA
Sin cuerpo JSON.

Liberar empleado:
POST http://localhost:8080/empleados/interno/{id}/liberar
Sin cuerpo JSON.

Turnos permitidos: MANANA, MAÑANA, TARDE, NOCHE, ROTATIVO.

7. RESERVATION - RESERVACIONES

Listar: GET http://localhost:8083/reservaciones
Buscar: GET http://localhost:8083/reservaciones/{id}
Agregar: POST http://localhost:8083/reservaciones
Modificar: PUT http://localhost:8083/reservaciones/{id}
Eliminar: DELETE http://localhost:8083/reservaciones/{id}

Cuerpo para agregar o modificar con asignacion automatica:
{
  "clienteId": "CLI-1001",
  "habitacionId": null,
  "tipoHabitacion": "DOBLE",
  "fechaIngreso": "2026-12-20",
  "fechaSalida": "2026-12-23"
}

Cuerpo alternativo indicando una habitacion existente:
{
  "clienteId": "CLI-1001",
  "habitacionId": 1,
  "tipoHabitacion": "DOBLE",
  "fechaIngreso": "2026-12-20",
  "fechaSalida": "2026-12-23"
}

Las fechas deben ser actuales o futuras y fechaSalida debe ser posterior a
fechaIngreso. El codigo y el estado son generados/controlados por el servicio.

Check-in:
POST http://localhost:8083/reservaciones/{id}/check-in
Sin cuerpo JSON.

Check-out:
POST http://localhost:8083/reservaciones/{id}/check-out
Sin cuerpo JSON.

Cancelar:
POST http://localhost:8083/reservaciones/{id}/cancelar
Sin cuerpo JSON.

Consultar cargo de habitacion por codigo:
GET http://localhost:8083/reservaciones/interno/{codigo}/cargo-habitacion

Modificar: PUT http://localhost:8084/pagos/{id}

{

  "metodo": "CREDITO"
}

Reembolsar una reserva:
POST http://localhost:8084/pagos/reservas/{codigo}/reembolso
{

}

Agregar un servicio adicional:
POST http://localhost:8084/cargos-adicionales
{
  "reservaCodigo": "RES-XXXXXXXX",

  "monto": 15000
}

GET http://localhost:8084/cargos-adicionales/reserva/{codigo}

GET http://localhost:8084/facturas/reserva/{codigo}

La factura consulta los cargos de habitacion, restaurante, estacionamiento y
servicios adicionales asociados al mismo codigo de reserva.

Listar: GET http://localhost:8086/limpiezas
Buscar: GET http://localhost:8086/limpiezas/{id}
Agregar: POST http://localhost:8086/limpiezas
Modificar: PUT http://localhost:8086/limpiezas/{id}

Cuerpo para agregar o modificar:
{
  "referencia": "LIMP-DEMO-001",
  "habitacionId": 1,
  "fecha": "2026-07-13",
  "tipo": "CHECK_OUT",
  "estado": "PENDIENTE"
}

Estados permitidos:

Finalizar una limpieza:
POST http://localhost:8086/limpiezas/{id}/finalizar
Sin cuerpo JSON.

Al completar el flujo normal, Cleaning publica CleaningFinished y Rooms deja
la habitacion nuevamente en estado DISPONIBLE.


11. ORDEN RECOMENDADO PARA UNA DEMOSTRACION

1. Abrir Eureka y comprobar que aparecen los siete servicios.
2. Consultar las habitaciones y empleados disponibles.
3. Crear una reservacion.
4. Aprobar su pago usando el codigo devuelto por Reservation.
5. Comprobar que la reserva queda confirmada y la habitacion reservada.
6. Ejecutar check-in.
7. Agregar consumo de restaurante, estacionamiento y cargo adicional.
8. Consultar la factura consolidada.
9. Registrar salida de estacionamiento antes de consultar la factura final.
10. Ejecutar check-out.
11. Comprobar la habitacion SUCIA y la tarea de limpieza asignada.
12. Finalizar la limpieza y comprobar la habitacion DISPONIBLE.


12. RESPUESTAS Y ERRORES FRECUENTES

200 OK: consulta o modificacion correcta.
201 Created: recurso creado.
204 No Content: eliminacion correcta o lista sin resultados en Reservation.
400 Bad Request: cuerpo JSON invalido o regla de negocio incumplida.
404 Not Found: identificador inexistente.
409 Conflict: estado o recurso incompatible con la operacion.

Si aparece Connection refused:
- Revisar que Eureka, RabbitMQ y los microservicios esten iniciados.
- Revisar el puerto correspondiente en esta guia.
- Si se usa Laragon, confirmar que MySQL este en 3306.
- Si se usa Docker, confirmar con: docker compose ps
